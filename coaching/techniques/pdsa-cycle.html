PDSA Cycle

Plan → Do → Study → Act is a learning cycle for testing a theory, studying the result and adapting the next action.

Core idea: Keep continuous improvement grounded in explicit learning rather than permanent actions chosen from one retrospective discussion.
PLAN→DO→STUDY→ACT→↺

Understand the method first

Plan

Define the goal, theory, prediction, measure and experiment.

Do

Run the experiment, preferably at a scale small enough to learn safely.

Study

Compare results with the prediction and understand what happened.

Act

Use the learning to adopt, adapt, abandon or design the next cycle.

Lineage: The W. Edwards Deming Institute describes PDSA as an integrated learning and improvement model rooted in Walter Shewhart’s work and developed through Deming’s practice.

How to use it

  1. State the improvement goal and theory about what is causing the problem.
  2. Make a prediction and choose evidence before changing the system.
  3. Run the smallest useful experiment.
  4. Study what happened against the prediction—not only whether people liked it.
  5. Act on the learning and start the next cycle.

Coach with it

Use the method as a lens for inquiry, not as a rigid prescription. Useful coaching questions include:

“What do we predict will happen and why?”

“What evidence would surprise us?”

“How small can we make this test while still learning?”

“What will we adopt, adapt or abandon after studying the result?”

Agile example

A team predicts that limiting active pull requests will reduce review delay. They test the limit for two weeks, study review time and aging, then adjust the policy based on evidence.

Watch for

Watch for

PDSA is not Plan → Do → Done. Study and adaptation are the learning engine.

Watch for

Do not scale an experiment before understanding what the first cycle actually taught you.
