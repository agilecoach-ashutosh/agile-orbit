WIP Limits

Set explicit limits on work in progress so new work is pulled only when capacity is available.

PROCESSWIP & QUEUE COACHINGRESEARCHED METHOD
← Back to WIP & Queue CoachingUnderstand the method ↓
Core idea: Reduce delay and context switching while exposing blocked work and capacity constraints.
Visualise WIP→Set limit→Stop starting→Start finishing→Adjust with evidence

Understand the method first

This method is best understood as a whole rather than as separate components.

Lineage: The Kanban Method uses explicit WIP limits and pull as core practices for balancing demand with capability and improving flow.

How to use it

  1. Visualise the actual workflow and count active work by state.
  2. Set an initial WIP limit that creates a useful constraint without making work impossible.
  3. When the limit is reached, swarm, unblock or finish work instead of starting more.
  4. Observe queue length, aging and cycle time.
  5. Adjust limits based on evidence as capability and demand change.

Coach with it

Use the method as a lens for inquiry, not as a rigid prescription. Useful coaching questions include:

“What do we do when a column reaches its WIP limit?”

“Which work should we help finish instead of starting something new?”

“What constraint becomes visible when we stop overloading the system?”

“Is the limit improving flow or merely being treated as a rule?”

Agile example

Test reaches its WIP limit. Developers stop pulling new stories and help resolve test data, defects and automation issues around the oldest items.

Watch for

Watch for

WIP limits without a team response can feel punitive.

Watch for

The purpose is flow and learning—not achieving perfect compliance with a number.
