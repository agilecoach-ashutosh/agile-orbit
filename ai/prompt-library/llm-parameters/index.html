01 • CREATIVITY DIAL

Temperature

Temperature controls how much variation the model allows when choosing its next token. Lower values make outputs more focused and predictable; higher values make them more varied and adventurous.

Creativity dial: Think of a brainstorming session. Turn the dial down for familiar, predictable ideas; turn it up to invite more unusual combinations and fresh possibilities.
Illustrative settingLikely feelGood starting use
0.1–0.3Steady, focused, less variationClassification, extraction, consistent formats
0.4–0.7Balanced and naturalBusiness writing, explanations, coaching dialogue
0.8–1.2More exploratoryBrainstorming, campaign ideas, creative writing

Example task: “Suggest ways to improve employee engagement in an Agile organization.”

  • At 0.2, expect safer and more conventional suggestions.
  • At 0.9, expect more varied angles and combinations.

Try this: Start at 0.7 for a general assistant. Lower it when consistency matters; raise it when exploring ideas. A higher value does not mean a more intelligent answer.

02 • VOCABULARY FILTER

Top-P (nucleus sampling)

Top-P limits the pool of likely next-token candidates. The model keeps the smallest group of candidates whose combined probability reaches the selected P threshold, then samples from that group.

Vocabulary filter: Imagine a filter that decides how wide the AI's shortlist of possible next words can be. A lower Top-P keeps only the strongest candidates; a higher Top-P allows a wider range of plausible words.

Example: The model is completing “The sprint review was…” and its possible next words have probabilities:

CandidateProbability
Useful45%
Constructive30%
Engaging15%
Unexpected10%

With Top-P = 0.75, the pool includes “Useful” and “Constructive” (together 75%). With Top-P = 1.0, all candidates remain eligible.

Try this: Leave Top-P at 1.0 initially and tune temperature first. Avoid aggressively changing both together because it becomes harder to tell which setting caused the difference.

03 • WORKING MEMORY

Context window

The context window is the amount of tokenized information a model can work with in one request or conversation turn. It can include instructions, chat history, supplied documents and the space needed for the response, depending on the model and API.

Working memory: Think of the amount you can keep in your mind while working on a problem. The context window is the AI's working space for instructions, conversation history and supplied material during a request.

Example: You provide a 40-page product strategy, customer feedback, delivery metrics and ask for a joined-up executive summary. A model with an appropriate context window may process more of that material together.

Remember: A larger context window is not permanent memory and does not guarantee perfect recall. Long inputs still need good structure, relevant retrieval and clear instructions.

Do I set it? Usually you select a model that supports the capacity you need. The available context limit is model-specific.

04 • ANTI-REPETITION & EXPLORATION DIALS

Frequency penalty vs presence penalty

Both can reduce repetitive output, but they work differently. In APIs that support them, these penalties adjust token selection based on what has already appeared.

Two different dials: Frequency penalty is the anti-repetition dial. It discourages tokens more strongly the more often they have appeared. Presence penalty is the exploration dial. It discourages using a token again simply because it has already appeared, nudging the model towards variety.

Frequency penalty: how often?

It applies more pressure against tokens that have appeared repeatedly. The more often a token has appeared, the stronger the frequency-based adjustment.

Presence penalty: has it appeared?

It applies a one-time presence-based adjustment when a token has appeared, encouraging the model to introduce different tokens and potentially new ideas.

SettingIllustrative effect
0No penalty adjustment
PositiveDiscourages repeated tokens / encourages variety
NegativeCan make repeated tokens more likely

Example: The draft says: “Agile improves collaboration. Agile improves delivery. Agile improves transparency.”

  • Frequency penalty may encourage less repeated use of “Agile” and “improves”.
  • Presence penalty can encourage moving on from already-used terms or ideas.

Try this: Start at 0.0. Test a modest positive value such as 0.2–0.5 only when repetition is a real problem. Too much penalty can make technical terms or important concepts disappear awkwardly.

05 • EMERGENCY BRAKE

Stop sequence

A stop sequence is a text marker that tells a compatible generation API to stop when that marker is produced. It is useful when an application expects a clear boundary.

Emergency brake: Think of a train's emergency brake. When the model generates a predefined stop marker, the API stops producing more text. It is a hard boundary for generation, not just a request to be brief.

Example: A simple coaching transcript format might be:

Coach: What would make this conversation useful?
Client: I want to understand why the team is stuck.
END_TURN

If END_TURN is configured as a supported stop sequence, generation stops when it reaches that marker. The marker is typically omitted from the returned text.

Useful for: transcript boundaries, legacy completion formats, structured multi-part generation and simple agent pipelines.

Important: Not every model or endpoint supports stop sequences. Check the exact API and model documentation. Do not use a stop marker that might occur naturally inside the answer.
06 • RESPONSE LENGTH LIMIT

Max output tokens

This sets the maximum number of tokens the model may generate in its response. It is a ceiling, not a promise that the model will use all of them.

Response length limit: Think of a word limit in an exam. You can write less than the limit, but you cannot exceed the maximum space allowed. Max output tokens sets that ceiling.

Example starting points:

Output token budgetTypical use
100–200Short answer or label
500Concise explanation
1,500–2,000Detailed response or report section
4,000+Long-form generation, when supported

Tokens are not words. A token may be a whole word, part of a word, punctuation or another text unit. The ratio varies by language and content.

Context window ≠ max output tokens. Context window is the total working space for input and output. Max output tokens limits how much the model can generate.
09 • PRACTICAL CONFIGURATION

How to combine these parameters

Think of the parameters as a team of controls, not seven independent magic switches. Start with the job you want the AI to do, choose a model with enough working memory, then tune the creativity and repetition controls to suit the task.

A useful rule: Start with a simple baseline. Keep Top-P at 1.0, leave repetition penalties at 0, and adjust temperature first. Change one setting at a time so you can tell what actually improved the answer.

How to choose your combination

  1. Start with the task. Accuracy, creativity or natural conversation call for different starting points.
  2. Choose the model and context window. Make sure the instructions, source material, conversation history and expected response can fit. Context window is generally a model capability, not a slider you tune in the prompt.
  3. Set the response length. Use a smaller output budget for short chat turns and a larger one for reports or detailed analysis.
  4. Set temperature first. Keep Top-P at 1.0 while you test. Temperature and Top-P both affect token selection, so changing both at once makes results harder to interpret.
  5. Add penalties only when needed. Begin at 0. If the output repeats itself, try a small positive frequency penalty. Use presence penalty carefully when you want more topic variety.
  6. Add a stop sequence only for a reason. It is useful for a defined output boundary, not normally needed for ordinary chat.
  7. Test with real examples. Run the same prompts against a small test set, compare quality and consistency, and change one parameter at a time.
These are starting presets, not universal best settings. Parameter ranges and support vary by provider, model and API endpoint. Some models do not support temperature, Top-P or repetition penalties. Use only settings supported by the model you selected.

A NOTE ON MODEL DIFFERENCES

These controls are not universal

Names, ranges, defaults and availability vary by provider, model and API endpoint. Some reasoning-oriented models do not expose sampling controls such as temperature, Top-P or penalties. Some APIs use max_output_tokens while others use a different field name. Context limits are model-specific too.

Always check the documentation for the exact model you are calling. Treat the values in this guide as learning examples, not universal settings or guaranteed optimal configurations.
