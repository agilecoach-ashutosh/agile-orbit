AI Task Decomposition

Turn a user story into a structured set of implementation-ready technical tasks for sprint planning.

Development Team / Technical LeadSprint PlanningDecompose + Analyze
PURPOSE

Why use this prompt?

Large user stories can hide significant implementation work. AI can help identify potential tasks across frontend, backend, database, APIs, infrastructure, security, testing and deployment.

COPY-READY PROMPT

Prompt

AGILE ORBIT / PROMPT
ROLE:
Act as a senior full-stack software engineer and Agile technical lead.

CONTEXT:
We are preparing the following user story for sprint planning:

User Story:
"As a user, I want to upload a profile picture to my account so that I can personalize my profile."

OBJECTIVE:
Decompose this user story into granular, implementation-ready technical tasks that a Development Team could add to a sprint backlog.

CONSIDER:
- Frontend/UI
- Backend/API
- Database and data model
- File storage
- Authentication and authorization
- File validation and security
- Error handling
- Automated testing
- Monitoring/logging
- Deployment/configuration

For each task, identify:
1. Task name
2. Layer/component
3. Brief description
4. Primary technology involved
5. Dependencies or prerequisites
6. Key acceptance/validation consideration

TECHNOLOGY CONTEXT:
Assume the application uses React for the frontend, Node.js/Express for the backend, PostgreSQL for the database, and AWS S3 for image storage.

OUTPUT:
Present the result as a structured table.

IMPORTANT:
Do not invent unnecessary architecture. If an implementation decision depends on information not provided, explicitly flag it as an assumption or question for the Development Team.

Copy the prompt as-is, then replace the input placeholders with your own context.

✦
Facilitation Tip

Ask the team: “What did AI identify that we might have missed?” Then reverse it: “What did AI assume incorrectly?” This turns AI output into a conversation starter rather than an answer.
