Kanban

Visualise work, limit WIP, manage flow and improve continuously.

Key takeaway: Kanban starts with the existing workflow and makes work visible. The team then manages flow through explicit policies, WIP limits and feedback.

Concept

Kanban starts with the existing workflow and makes work visible. The team then manages flow through explicit policies, WIP limits and feedback.

What happens in teams

Useful signals include throughput, cycle time, work item age and blocked time. Look at distributions rather than relying on a single average.

Agile implication

The goal is not a perfect board. The goal is a better flow of value through the system.

What you can do

  1. Make the current system visible.
  2. Ask one question that challenges an assumption.
  3. Run a small, reversible experiment.
  4. Inspect evidence and decide what to do next.

Practical example

Choose one recurring friction—handoffs, unclear priorities, excessive WIP or delayed feedback. Map the path from request to outcome, identify where waiting occurs and test one change with the people doing the work.
